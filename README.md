# 环评受理单位 → 审批机构清单 → 官网受理公示入口

从青绿数据（i-esg.com）的环评受理列表里提取「受理单位」，清洗成各省的环评审批机构清单，
再逐个找到这些机构在政府网站上发布受理公示的栏目。最终产物是每省一张「受理单位主数据表」
（一机构一行：名称、行政区划、开发区归属、职能、受理公示入口、核验依据、数据佐证），同步到飞书。

用途：下游按这些入口去抓环评受理公示——**受理阶段是唯一能稳定拿到环评报告全本的阶段**
（安徽、浙江都抽样验证过，见 `docs/浙江记录.md` 第二节）。

## 现状（2026-10-09）

| 省 | 青绿受理记录（清洗后） | 单位 | 审批机构 | 入口核验情况（审批机构） |
|---|---:|---:|---:|---|
| 江苏 | 84,168 | 334 | 244 | 已核实 167 · 访问受限 50 · 未核实 22 · 无独立环评栏目 5 |
| 安徽 | 56,311 | 455 | 323 | 已核实 321 |
| 浙江 | 109,894 | 252 | 178 | 已核实 142 · 推断 35 · 未核实 1 |

「审批机构」= 生态环境部门、行政审批 / 数据局 / 政务服务、开发区管委会；交通、水务、人民政府等只是公告发布渠道，
留在完整表里但不交付。「已核实」= 打开栏目看到了该单位的受理公告；「推断」= 填了最可能的栏目但没看到本单位条目
（多是 2019 年前的旧机构名），依据写在备注里。

## 产物

| 文件 | 内容 |
|---|---|
| `<省>受理单位主数据.csv` | **主交付**，41 列，编号 `JS` / `AH` / `ZJ` 开头、一次分配不变 |
| `<省>环评单位.csv` / `<省>环评审批机构.csv` | 清洗结果：完整表 / 交付口径 |
| `<省>环评单位_官网及公示入口.xlsx` | 入口表（人工核对用） |
| `entries/<市编码>_<市名>.csv` | 入口的权威录入：每单位的受理公示栏目、核验情况、依据 |
| `refs/` | 入库的参照快照：行政区划树、开发区维表、受理 / 监督共现关系、入口表、公示栏目清单 |

## 流程

```
青绿地区树 → 分市抓取 raw/ → 清洗合并 → <省>环评单位.csv / 审批机构.csv → 飞书比对表
                                              ↓
                       entries/（人工 + 脚本找入口、核验） → build_authority_master.py → <省>受理单位主数据.csv → 飞书
```

换省按 `docs/新省份操作手册.md` 的八步走，代码不用改。

## 运行

依赖 Python 3.12、`httpx`、`pycryptodome`。抓青绿需要登录令牌，只通过 `--prompt-token` 在终端输入，不写进文件。

```bash
.venv/bin/python crawl_jiangsu_eia.py --province 330000 --tree-only --prompt-token   # 取地区树
.venv/bin/python gen_city_scripts.py --tree trees/330000_浙江省.json                  # 生成分市脚本
.venv/bin/python merge_jiangsu.py --province 330000                                  # 全省合并清洗
.venv/bin/python build_authority_master.py --province 330000                         # 重建主数据
.venv/bin/python scripts/dev.py check                                                # lint + 离线回归测试
```

（脚本名带 `jiangsu` 是历史原因，按 `--province` 通用。）
