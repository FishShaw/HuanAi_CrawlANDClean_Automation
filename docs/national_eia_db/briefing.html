两件套对接讲解

用 50 分钟讲清三件事：我们要交付什么，爬虫要抓哪些字段，两份文件怎么认成同一个审批事项。表怎么建由研发决定，这里只讲结果、理由和验收标准。

对象 爬虫与数据库研发 时长 约 50 分钟 配套 FigJam 流程图 · 设计文档（参考实现）

讲之前先定下的讲法

  • 从结果讲起先给研发看一行最终交付数据，再倒推为什么要抓这些字段。先讲表结构，研发只会去讨论表怎么建。
  • 用真实项目走一遍拿昆山唯斯达这个项目，从受理公示到批复公告完整走一遍。一个具体例子比十条规则好懂。
  • 每个字段说清用途字段按「它帮我们回答什么问题」来讲。研发知道用途，才能在网站结构不一样时自己找替代来源。
  • 分清两类要求明确告诉研发哪些是业务上必须做到的，哪些由他们决定。边界说清楚，研发才愿意承担实现。
  • 用验收用例代替字段规范给研发十几个「遇到这种情况应该得到什么结果」。怎么实现都行，用例过了就算对。
  • 设计文档只作参考已有的表结构和 SQL 是一套跑通过的参考实现，会后再发，别在会上逐表讲。

1我们要交付的是什么5 分钟

程序是怎么认出这是一件事的：

  1. 两条公告都列了好几个项目，先把每条公告拆成「项目行」，文件也要挂到对应的行上。
  2. 项目名原文带顿号，规范化（去标点、全角转半角、去掉「关于……的批复」外壳）后两边一致；建设单位也一致。
  3. 检查有没有冲突：同一个审批机关，受理日早于批复日，都是报告表。没有冲突，认成同一个事项。
  4. 批复附件名里有文号「昆高环建〔2026〕63号」，记到这个事项上。以后再出现同一文号，直接归到这里。
  5. 按「批复公告 → 拟审批公示 → 受理公示」依次找报告：9 月 14 日批复公告只附了批复，9 月 7 日拟审批公示没有附件，所以报告用 8 月 31 日受理公示版，标记「兜底」，同时记下「拟审批公示已经抓到」，这个事项不会再被当成「可能有更好版本」去补抓。

审批阶段真的附了报告的例子

批复公告里附报告：常熟高新区林森新建石墨舟及石墨双极板生产项目。2024-05-07 受理公示附了《……环评报告表-公示稿.pdf》，2024-05-20 作出审批决定的公告里又附了一份同名的《……环评报告表-公示稿.pdf》，外加《林森批复.pdf》。按规则，报告取批复公告里的那一份。

受理和拟审批合并公示：苏州工业园区 2026-09-03 的合并公示里，铭青机电附的是《（报批稿）铭青机电-环评报告.pdf》。合并公示按审批阶段算，不算兜底。

两个细节要注意：受理和拟审批合并发布的公示，要当成审批阶段；批复公告里附的报告，可能和受理版是同一个文件，比一下文件内容哈希就知道，不用人工判断。

现实预期：按苏州现有爬虫的匹配结果，范围内已批复、找到报告的 101 个项目里，报告来自审批阶段的只有 5 个；范围内的批复公告附报告的只有 4 / 323。兜底会是常态，所以每个兜底都要分清是「审批阶段查过、确实没有」，还是「审批阶段的公告还没抓到」。上海市局平台在审批决定公告的项目页里挂报告，情况可能不同，需要逐站确认。

再补一个例子：网站自带的跨阶段编号

苏州工业园区（铭青机电、域展精密五金等项目）的受理页和批复页，链接里带着同一个 flowInstId=5f7f5b4dc292433395bb1a9af17bf0d1。这是系统里的办件编号，比名字可靠得多。

写解析时，看到这种在受理和批复之间保持不变的编号——项目代码、办件号、流程 ID——一定要单独存下来，它就是最好的配对依据。

6怎么配对，怎么选文件7 分钟

配对就像认人：身份证号比手机号可靠，手机号比「姓名加生日」可靠，只有名字像的，只能先认下，再找人核实。

顺序依据例结果
1报告和批复挂在同一个项目行上海市局平台的项目页直接认
2跨阶段编号相同园区 flowInstId、投资项目统一代码直接认
3批复文号相同昆高环建〔2026〕63号直接认
4建设单位 + 项目名规范化后完全一致昆山唯斯达直接认
5只是名字相似公司简称、项目改名认，交付时标「待复核」，并派人核对

一票否决，不管上面哪条依据成立：不是同一个审批机关（也不在同一个发布范围）；批复日期早于受理日期；一边是报告书一边是报告表；这个批复已经配给了别的事项。

每次配对都要记下：用了哪条依据、强弱或分数、由哪版规则或哪个人判定的。

选文件

  • 报告：审批阶段优先：批复公告里附的 → 拟审批公示里附的（受理和拟审批合并公示也算这一档）→ 受理公示版（兜底，要标记）。同一阶段有多份时，先看版本字样（报批稿 → 送审稿 → 公示稿），再取最新、能打开的。
  • 兜底要说清：用了受理版的，要区分「这个事项的拟审批公示抓到了，确实没附报告」和「还没抓到」。后一种要去补抓；以后抓到审批阶段的报告，交付结果自动换成新的。
  • 批复：审批决定公告里的批复文件；批复只写在网页正文里的，把正文存成 PDF。
  • 两份都要来自官方网站、能打开；建设单位自己发的全本公示不算。

分数怎么打、相似度用什么算法，你们定。我只要求三点：强证据优先用，有冲突就否决，每次判断留下依据。

7哪些必须做到，哪些你们决定4 分钟

必须做到（验收看这些）

  1. 每份交付文件都能追到：文件链接 → 公告页 → 栏目 → 审批机关。
  2. 抓到的原始数据不覆盖、不删除；网站撤稿了也能查到。
  3. 每次配对留依据；规则改了能重跑，人工确认过的结果不丢。
  4. 交付清单只包含：两份文件齐全、能打开、来自官方网站、在范围内的事项；靠弱依据配上的带「待复核」标记。
  5. 在范围内却没交付的事项，写明缺哪份、为什么：没抓到、网站翻不到、只在网盘或第三方、文件打不开、还没批。
  6. 业务口径做成可配置：起始日期、报告优先级、范围规则、官方网站名单、待复核门槛。

你们决定

  • 用什么数据库，表怎么拆、怎么命名。
  • 爬虫框架、调度、重试和限速策略。
  • 名称规范化和相似度算法，分数取值。
  • 文件存储、格式转换、OCR 方案。
  • 校验放在数据库约束里还是程序里。
  • 待复核的界面和流程怎么做。

设计文档里的表结构和 SQL 是一套能跑通的参考实现，已经用测试数据验证过。你们可以整体换掉，只要下面的验收用例都能过。

9请研发回答的问题5 分钟

最后留时间让研发说。这些答案决定排期，也决定哪些「必须」字段要按网站打折扣。

  1. 上海 15 个 scraper 和苏州爬虫，能不能统一按上面的字段输出？改动量有多大？
  2. 哪些网站只能拿到公告列表，拆不出「公告里的每个项目」这一层？
  3. 在已经爬过的网站里，见过哪些跨阶段不变的编号？
  4. 2021 年以来的文件量、存储和 OCR 成本大概多少？
  5. 待复核的事项由谁核、在哪里核？
  6. 先用苏州数据做第一阶段验收，需要多长时间？
