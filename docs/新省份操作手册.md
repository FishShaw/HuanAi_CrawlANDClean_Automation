# 新省份操作手册：环评受理单位提取 → 清洗 → 飞书比对 → 官网入口

江苏已完整跑通（结果见 [江苏试点记录.md](江苏试点记录.md)）。换一个省，照下面八步走，
**代码不用改**，只换省编码。脚本文件名里带 `jiangsu` 是历史原因，逻辑对全国通用。

> 数据源：青绿数据 i-esg.com「环评受理」列表的「受理单位」列（接口字段 `processDepartment`）。
> 这一列是**公告的发布单位**，不是法律意义上的审批机关——第 5 步会按审批机构口径再筛一次。

## 0. 准备

| 需要什么 | 怎么拿 |
|---|---|
| Python 环境 | 仓库根的 `.venv`（依赖只有 `httpx`、`pycryptodome`，走代理时再加 `socksio`） |
| 青绿登录令牌 | 浏览器登录 i-esg.com → 开发者工具 → 任一 `doAction` 请求头 `Authorization` 里 `Bearer ` 之后那段。**不要贴进聊天或写进文件**，运行时用 `--prompt-token` 隐藏输入 |
| 省编码 | 6 位行政区划码，如浙江 `330000`、北京 `110000`（直辖市自动把全市当成一个「市」） |
| 飞书比对表（第 6 步用） | 按江苏那张的格式建好子表：A 代码 / B 省 / C 市 / D 区县，每个代码一行，E–L 空着 |
| lark-cli（第 6 步用） | `lark-cli auth status` 确认 user 身份 ready |

## 1. 取地区树，生成分市脚本

```bash
.venv/bin/python crawl_jiangsu_eia.py --province 330000 --tree-only --prompt-token
.venv/bin/python gen_city_scripts.py --tree trees/330000_浙江省.json
```

地区树来自站点接口，所有地名白名单都从它生成，**不要手写地名**。生成的 `cities/crawl_*.py`、
`cities/clean_*.py` 只是固定了省、市编码的薄封装。

## 2. 逐市抓取

```bash
read -rs I_ESG_TOKEN && export I_ESG_TOKEN && for f in cities/crawl_33*.py; do .venv/bin/python "$f" || break; done
```

- 每抓完一个市原子写盘到 `raw/<市编码>_<市名>.json`。中断（额度 100006、限流、Ctrl-C）后重跑同一条命令，已完成的市自动跳过。
- 接口 `total` 封顶一万且不报错，脚本会按公告日期自动二分。**看输出里有没有「截断警告」**——有就说明单日超一万，需要人工处理。
- 同一会话内反复全量拉取会被限流到请求挂起，别连续重跑。

**检查点**：每个市「抓到」条数和接口 total 一致；个别市明显偏少时（江苏徐州只有 1192 条），先确认没撞封顶，再认定是站点收录少。

## 3. 逐市清洗（只用来核对）

```bash
for f in cities/clean_33*.py; do .venv/bin/python "$f"; done
```

输出在 `by_city/`，用来逐市看结果和删除清单。**全省表不要拼这些 CSV**——省厅、生态环境部在每个市都出现，拼接会重复计数。

## 4. 全省合并

```bash
.venv/bin/python merge_jiangsu.py --province 330000
```

产出两份：

| 文件 | 内容 | 用途 |
|---|---|---|
| `浙江省环评单位.csv` | 全部单位，带「职能」列 | 完整备查 |
| `浙江省环评审批机构.csv` | 只留 生态环境 / 行政审批 / 开发区管委会 | **对外交付用这份** |

**检查点**：
- 输出里 `保留 + 空 + 删除 = 原始条数`，对不上说明清洗漏算。
- 看「删除（不规范）」「删除（标错地区）」前 15 条，确认删的确实是残句、代称、外省单位。

## 5. 人工过一遍分类（15 分钟）

新省份几乎一定会冒出江苏没见过的写法。重点看三处：

0. **先看职能构成**：`awk -F, 'NR>1{print $4}' <省>环评单位.csv | sort | uniq -c`。
   江苏是「行政审批/数据局占大头」，安徽是「生态环境系统占 98.6%」，两省形态完全不同；
   记录数占比最高的那类就是该省的主要发布口，其余类别要逐个确认是不是漏认的审批机构。
1. **完整表里「职能=其他部门」的单位**，按记录数倒序看前 20 个。记录数多的（江苏的「兴化市发改委」45 条、淮安「经开区分局」119 条）要确认：是真不是审批机关，还是写法没被规则认出来。认错的改 `clean_jiangsu_eia.py` 的 `ROLE_*` 正则后重跑第 4 步。
2. **单位数异常少的市**：可能是市名和区县名相同（江苏淮安/淮安区）导致被并成一条，查该市有没有一条记录数大得离谱的单位。
3. **开发区归属**：`地区` 列里「本级开发区」「XX高新区」这类，确认没有把两个不同开发区并在一起。

改规则后跑 `.venv/bin/python scripts/dev.py check`：江苏输出必须逐字节不变，否则要能逐条解释差异并连同新 CSV 一起提交。改动一律走 `scripts/dev.py start` 开分支，推到 GitHub 提 PR 合并（主干禁止直推，见 CLAUDE.md「分支保护与改动流程」）。

## 6. 填飞书比对表

```bash
.venv/bin/python fill_compare_sheet.py --url <飞书链接> --sheet-id <子表id> --province 330000        # 先看计划
.venv/bin/python fill_compare_sheet.py --url <飞书链接> --sheet-id <子表id> --province 330000 --run  # 写入
```

脚本会：按代码把审批机构挂上去（市本级→市行、省级→省行），一个代码多个单位就在下面插行、一单位一行；
写完回读逐格核对。同时生成 `<省>比对_无区县代码的单位.csv`。

**只在表格是空白模板、或已和本地结果一致时才会写**；有人手工改过就拒绝写入，避免覆盖。

把「无区县代码」清单发给需求方确认：开发区能明确对应某个区县的（江苏的苏州高新区→虎丘），
确认后加进脚本顶部 `ZONE_DISTRICT` 对应省的映射，重跑。**没确认的不要自己归**。

## 7. 查官网和公示入口（最耗时，按市分批）

对 `<省>环评审批机构.csv` 里每个单位，找四个入口：首页、受理公示、审批前（拟审批）公示、审批后（批复）意见，
录入 `entries/<市编码>_<市名>.csv`（列同江苏）。约定：

- 没有分栏、三类混在一个栏目的，把同一个地址重复填进相关列，备注写明。
- 「核验情况」四选一：**已核实**（打开栏目页看到了环评条目）/ **未核实**（只来自搜索结果）/ **访问受限**（403 等）/ **无独立环评栏目**。判断依据写进备注，**看起来像不算已核实**。
- 按 (城市, 单位) 录入——同名单位在不同市是不同机构。

江苏经验：先查市局，区县局常常就在市局同一个栏目里（连云港、宿迁）；审批职能可能在数据局（无锡、南通）；
各市体制差异很大，不要套用上一个市的模式。全部录完做一轮统一核实，江苏这一轮查出 3 条原先给错的栏目。

```bash
.venv/bin/python build_entries_xlsx.py   # 目前写死江苏，换省要改顶部路径和标题（见下）
```

## 8. 收尾检查

- [ ] 第 2 步没有截断警告
- [ ] 第 4 步条数守恒
- [ ] 第 5 步其他部门前 20 个过过目
- [ ] 飞书表回读一致，无区县代码清单已发给需求方
- [ ] 入口表每行都有核验情况和依据

## 与需求方确认过的口径（2026-09-15 ~ 09-17，换省沿用）

1. 只抓**环评受理**模块。
2. 清洗：标错地区删、不规范名称删、同地区同职能的不同写法并成公告日期最新的规范写法。
3. 交付用审批机构口径：生态环境部门、行政审批 / 数据局 / 政务服务、开发区管委会。交通、水务、司法、人民政府等只是发布渠道，拿掉；完整表留底。
4. 行政审批局、数据局**可以是**真正的审批机关（相对集中行政许可），不能按「只有生态环境局审批」去删。
5. 飞书表一单位一行；没有单位的代码留空；没有区县代码的单位不填，列清单给需求方。
6. 官网入口不硬查「其他部门」，只给主页。
